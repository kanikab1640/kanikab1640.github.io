🧭 What This Project Is

oncology-rwe-nsclc is a teaching and demonstration project for real-world evidence in oncology. In plain terms: it shows how a pile of messy medical records can be cleaned, organized, and turned into a trustworthy answer to a clinical question — in this case, how long patients with non-small cell lung cancer (NSCLC) survive after diagnosis.

The project uses pretend patient data. The records are generated by a tool called Synthea, which invents realistic but completely artificial medical histories. Nothing in this project comes from a real person, a real hospital, or a real registry. It is a methods demo — a way to learn, test, and compare approaches without touching protected health information.

Everything happens in a repeatable pipeline. The fake records are translated into a common international format called the OMOP CDM, a group of NSCLC patients is assembled using dbt and PostgreSQL, and survival statistics are calculated in R. Those results are then compared against published patterns from the SEER cancer registry, so you can see how close — or how far — the synthetic world is from reality.

✨ What Makes It Useful

🧪 Synthetic by design

Every record is generated from scratch. You can share, publish, and experiment freely because no real patient is involved.

🔗 Standards-based

Data is harmonized to the OMOP CDM, the format used by major research networks, so the skills transfer directly to real projects.

🧱 Built with dbt

The NSCLC cohort is assembled with documented, testable transformation steps that run on PostgreSQL.

📈 Survival analysis in R

Kaplan-Meier curves and survival estimates are produced in R and compared against SEER registry benchmarks.

✅ Quality checks included

Automated checks flag missing values, impossible dates, and broken links between tables before results are trusted.

📚 A documented failure

The project includes a real write-up of a case where the synthetic data failed validation — and what that teaches us.

  4. Install R and RStudio. Download R from cran.r-project.org for Windows, then download the free RStudio Desktop from posit.co/download/rstudio-desktop. Install R first, then RStudio. Both use simple installer wizards with a Next button throughout.
  5. Install Python and dbt. Download Python from python.org/downloads and, on the very first installer screen, tick the box that says Add Python to PATH before clicking Install. This one checkbox saves a lot of confusion later. Once Python is installed, open the Start menu, type cmd, and open the Command Prompt. Type pip install dbt-postgres and press Enter. Wait for the text to stop scrolling.
  6. Connect the pieces. Return to the extracted project folder. The README explains which small settings file to edit so the project knows your PostgreSQL password and port. Change the two values exactly as shown in the README, save the file, and close it.

  9. Produce the survival results. Open RStudio, use File → Open File to load the survival analysis script from the project's R folder, and click Source. The script writes the survival curves and comparison tables to an output folder. Open those files to see the results next to the SEER benchmarks.

Most tutorials only show what works. This project does the opposite in one important section: it documents a case where the synthetic data failed validation. The generated records looked plausible at first glance, but the quality checks caught a mismatch that would have quietly distorted the survival results.

That section walks through how the problem was spotted, how it was investigated, and what it means for anyone using synthetic data as a stand-in for real patients. ❓ Common Questions

Is this real patient data?

No. Every record is synthetic, produced by Synthea. There is no real patient information anywhere in the project, which is exactly why it can be shared openly.

Do I need to know how to code?

No. You will copy and paste a handful of commands exactly as written in the README. No programming knowledge is required to get the full pipeline running.

Why does the synthetic data disagree with SEER?

Because it is synthetic. The comparison is the point: it shows where simulation matches reality and where it does not. The documentation explains each difference.

Can I use this for my own study?

Use it as a template and a learning tool. Any real-world study needs real, properly governed data and the appropriate approvals.
